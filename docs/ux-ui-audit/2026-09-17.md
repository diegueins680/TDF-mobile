## Confirmed finding UX-260917-005

On signup, `Linking.openURL` rejection for account terms/privacy escaped without
user feedback. A browser unavailable/offline failure must preserve the input and
provide an explicit retry. The patch catches the rejected launch, announces
Spanish/English recovery next to the links, and wraps the links for larger text.
It does not change policy versions, grant consent, submit registration or navigate
to another account. Failure recovery is a UI concern; no backend/API change.

Acceptance: rejected link launch announces an actionable alert, keeps the typed
email, never submits signup, and a second tap retries the same policy URL. Existing
44-point link text height is retained. Actual large-font and screen-reader behavior
still requires native testing; a React Native rendered test is not that evidence.
